# План: единый контур RePanel site в Yandex Cloud

Спецификация: [`../specs/2026-08-04-yandex-data-plane.md`](../specs/2026-08-04-yandex-data-plane.md)

## 1. Сохранение исходного состояния

- [ ] Снять новые полные экспорты Supabase и YDB без вывода секретов в логи.
- [ ] Составить канонический JSON-манифест по всем десяти коллекциям: количество,
      размер и SHA-256.
- [ ] Сохранить конфигурационный манифест бакетов и число объектов.
- [ ] Загрузить экспорты в приватный версионируемый backup-бакет Yandex.
- [ ] Скачать копии обратно и повторно проверить SHA-256.

## 2. PostgreSQL и серверный слой

- [ ] Добавить идемпотентную SQL-схему `site_records` с ограничением коллекций и
      уникальными индексами.
- [ ] Реализовать серверный PostgreSQL-адаптер для фактически используемого
      PostgREST-подмножества.
- [ ] Заменить `SupabaseClient` в серверных типах и вызовах на локальный тип БД.
- [ ] Перевести страницы каталога на серверную БД.
- [ ] Добавить read-only `/api/catalog/products` и перевести апселл корзины на
      этот API.
- [ ] Добавить `/api/health` с проверкой БД и режима запрета записи.
- [ ] Добавить серверную защиту мутаций через `CUTOVER_WRITE_FREEZE`.

## 3. Yandex Object Storage

- [ ] Добавить серверный клиент S3-compatible Object Storage.
- [ ] Перевести административную загрузку изображений с Supabase Storage.
- [ ] Ограничить допустимые типы, размер и ключи объектов как сейчас.
- [ ] Обновить Next image remote patterns на точный домен Yandex Storage.

## 4. Удаление runtime-зависимостей

- [ ] Удалить публичный Supabase-клиент и перенести типы магазина в нейтральный
      модуль.
- [ ] Удалить Supabase/YDB runtime-пакеты и build args.
- [ ] Обновить проверку российского деплоя под PostgreSQL/Object Storage.
- [ ] Оставить исторические скрипты только там, где они нужны для проверяемого
      one-shot экспорта, либо заменить их нейтральным импортом.
- [ ] Проверить, что клиентские артефакты не содержат старых URL/ключей.

## 5. Автоматические проверки

- [ ] Добавить unit-тесты фильтров, проекции, кардинальности и write freeze.
- [ ] Добавить тесты API опубликованного каталога и health.
- [ ] Выполнить `npm run lint`, `npm test` и production build.
- [ ] Выполнить контейнерный smoke локально с временным PostgreSQL.

## 6. Теневой контур Yandex

- [ ] Создать отдельную роль и базу `repanel_site` в существующем PostgreSQL.
- [ ] Создать версионируемый бакет изображений и минимальный сервисный аккаунт.
- [ ] Собрать amd64-образ с неизменяемым тегом commit SHA.
- [ ] Развернуть контейнер с read-only rootfs, лимитом памяти и внутренним портом.
- [ ] Подключить теневой домен через Caddy и проверить TLS.

## 7. Импорт и верификация

- [ ] Импортировать исходные документы без преобразования полей.
- [ ] Сравнить количества и канонические SHA-256 по каждой коллекции.
- [ ] Снять `pg_dump`, загрузить в backup-бакет и проверить скачивание.
- [ ] Восстановить дамп во временную БД и повторить сверку.
- [ ] Проверить существующие товары, два заказа и четыре события истории.
- [ ] Выполнить обратимые create/update/delete smoke-тесты только на тестовой
      записи теневого контура.

## 8. Переключение и наблюдение

- [ ] Остановить старый write-path, снять финальную дельту и повторить сверку.
- [ ] Переключить `site.re-panel.ru` на VM, не меняя Vercel-редиректы.
- [ ] Проверить TLS, страницы, админку, checkout validation и webhook endpoint.
- [ ] Перевести прежний Serverless Container в rollback-only состояние.
- [ ] Подтвердить ежедневный backup и успешное контрольное скачивание.
- [ ] Наблюдать новый контур 14 дней до отдельного решения об отключении старых
      ресурсов.
