# Российский serverless-контур RePanel

Дата актуализации: 28.07.2026.

## Что переносится

Минимальный контур включает только данные клиентов:

- `shop_orders` — заказы, контакты, адреса, согласия и статусы оплаты;
- `order_timeline` — история действий по заказу;
- `returns` — возвраты;
- `certificates` — подарочные сертификаты, если они содержат сведения получателя.

Каталог товаров, публичные изображения и промокоды не содержат персональных
данных и временно остаются в Supabase.

## Инфраструктура

- YDB Serverless `repanel-personal-data`;
- регион `ru-central1`;
- лимит хранилища 1 ГБ;
- лимит нагрузки 10 RU/с;
- выделенная пропускная способность 0 RU/с;
- сервисный аккаунт `repanel-app` с ролью `ydb.editor`;
- приложение в Yandex Serverless Containers с нулевым числом постоянно
  запущенных экземпляров.

Фиксированная оценка YDB в консоли — 0 ₽/мес. Фактическая плата появляется
только при выходе за бесплатные лимиты или при использовании дополнительных
ресурсов.

## Переменные приложения

```text
PERSONAL_DATA_BACKEND=ydb
YDB_CONNECTION_STRING=grpcs://ydb.serverless.yandexcloud.net:2135/?database=/ru-central1/...
YDB_METADATA_CREDENTIALS=1
YDB_PERSONAL_DATA_TABLE=personal_data_records
```

Секреты Supabase, Точки, СДЭК и административного доступа задаются только в
настройках ревизии контейнера. Они не записываются в образ и репозиторий.

## Миграция

Таблица создаётся командой:

```bash
npm run ydb:init
```

Копирование и сверка:

```bash
npm run ydb:migrate
npm run ydb:verify
```

Для разового запуска с компьютера допускается временный авторизованный ключ
сервисного аккаунта. После проверки ключ необходимо отозвать и удалить локальный
файл. В рабочем контейнере ключ не используется: IAM-токен выдаётся через
metadata service.

## Безопасное переключение

1. Развернуть ревизию Serverless Container, не меняя публичный DNS.
2. Проверить `/privacy`, `/personal-data-consent`, каталог и административную
   панель.
3. Создать тестовый заказ с минимальной суммой и убедиться, что запись появилась
   в YDB.
4. Сверить число заказов и событий командой `npm run ydb:verify`.
5. Переключить домен на проверенную ревизию.
6. Убедиться, что новые заказы появляются только в YDB.
7. Удалить старые копии персональных данных из Supabase после контрольного окна
   и оформить внутренний акт удаления.

До пункта 6 старый сайт нельзя описывать как полностью переключённый на
российское хранилище. До пункта 7 Supabase остаётся временной исторической
копией, а не рабочим местом обработки.
